# CLAUDE.md

## Must-follow constraints
- `themes/hugo-theme-cleanwhite/` used to be tracked as a git **gitlink** (a nested repo with its own `.git`, pointing at `zhaohuabing/hugo-theme-cleanwhite`) with no `.gitmodules` registering it — that silently broke CI, since a fresh `actions/checkout` got an *empty* theme directory. This has been fixed: the nested `.git` was removed and the theme is now vendored as ~174 plain tracked files directly in this repo, same as everything else. Do not re-introduce a nested `.git` in this directory (e.g. by `git clone`-ing a fresh copy of the theme over it) — that would silently reintroduce the CI-breaking gitlink.
- The theme has been **hand-patched in place**: `layouts/partials/nav.html`, `layouts/partials/multilingual-sel.html`, `layouts/partials/head.html` (title format, hreflang links; `zanshang.min.css` only loads when `reward` is on, `lazysizes.min.js` intentionally not loaded, header image via `partialCached`), `layouts/partials/post_list.html` + `pagination.html` (i18n strings), `layouts/partials/search-pagefind.html` (Turkish UI strings only on the TR site), `layouts/partials/footer.html` (third-party ghbtns.com iframe and jsDelivr fastclick loader removed for privacy/supply-chain reasons; don't re-add), `layouts/_default/single.html`, `layouts/_default/baseof.html`, `layouts/_default/post.html`, and `layouts/_default/list.algolia.json` are locally modified inside `themes/hugo-theme-cleanwhite`, and `layouts/partials/sidebar.html` / `archetypes/post.md` were deleted there. Do not "clean up" or reset the theme to match its upstream remote — that destroys these local fixes. Since the 2026-10-10 redesign the theme's `baseof.html`, `head.html`, `nav.html`, `footer.html` and list/single templates are **no longer rendered** (site-level layouts replace every page kind, see "Layout resolution"); the site still uses the theme's `partials/webp-image.html` (og:image) and shortcodes. Removing the theme entirely is a planned, separate step that needs the member's explicit yes.
- `public/` is **only a build output directory** (git-ignored, regenerated by `hugo`). It is not, and never was, its own git repository — an earlier version of this doc claimed otherwise; that was wrong. Never hand-edit files under `public/`.
- The site is **bilingual (since 2026-10-09)**: English is the default language at `/`, Turkish lives under `/tr/` (`[languages]` in [hugo.toml](hugo.toml)). Every page gets both versions as translation pairs: `foo.md` + `foo.tr.md` (or `index.md` + `index.tr.md` in a bundle). Per-language title/slogan/SEO params and menus live under `[languages.en]` / `[languages.tr]`, UI strings in [i18n/](i18n/). The language switch in `layouts/partials/site/header.html` links to the page's translation, falling back to that language's home.
- Menu URLs are written **with the language prefix** (`/tr/projeler/`) and rendered with `relURL`, not `relLangURL`, so single-language static pages like `/kart/` don't become `/tr/kart/`. Write in-content links the same way: full path including `/tr/` for Turkish pages.
- `markup.goldmark.renderHooks.link.useEmbedded = "never"` is required: on multilingual sites Hugo auto-enables its embedded link hook, which tries to publish `/kart/` (a `static/` folder also mounted as `assets`) as a resource and breaks the build.
- Positioning: this is an AI Automation Consultant portfolio + case studies site, not a cybersecurity blog. Only cite projects from the "Public proof" list in `~/Desktop/Ajanlarım /context.md`; label demos as demos; never use "Engineer" as a job title before graduation. A post's type is its first category, one of `case-study`, `field-note`, `research` (labels and icons come from i18n `type-*` keys and `partials/site/icon.html`); tags are ASCII slugs (`n8n`, `python`, `ai-agents`, `automation`). Titles don't repeat the type ("Case study: ...") since the type label shows it. `ai_use` (`edit` | `draft`) adds the AI-use note under a post; only set it to what is actually true for that post.
- No em dashes in published copy.
- Personal data: the only contact email anywhere on the site (including `/kart/`) is `muharremmeric.ordu@gmail.com`. Never add a phone number, WhatsApp link, or any other personal email. Commits must use the GitHub noreply author email already set in `git config`; GitHub rejects pushes with a private address.
- The main site runs under a meta CSP (`layouts/partials/site/head.html`): `script-src 'self' 'wasm-unsafe-eval'` (WASM is for Pagefind), `style-src 'self'`, `img-src 'self' data:`. No inline `<script>`/`<style>`, no `style=`/`on*=` attributes, no external resources; put JS/CSS in `assets/` through Hugo Pipes. Don't loosen the policy to fix a violation without finding its cause first. Pagefind excerpts are rendered without `innerHTML` (only `<mark>` becomes an element); keep it that way.
- `/kart/` runs under a strict CSP: no inline `<script>`/`<style>`, no `onclick`, no external resources. JS lives in `static/kart/kart.js` (vCard), the QR code is `static/kart/qr.svg`, styles come from the precompiled `static/kart/kart.css` (Tailwind v3.4.17 standalone CLI). A new Tailwind class in `index.html` will not work until `kart.css` is rebuilt; the Tailwind input/config were not kept, so recreate them (outside `static/`, e.g. `tools/kart/`) before the first class change.
- CI pins: pagefind is pinned to 1.5.2, actions are pinned by SHA, and the Hugo `.deb` is verified with `HUGO_SHA256` in [.github/workflows/hugo.yaml](.github/workflows/hugo.yaml). Bumping the Hugo version means updating `HUGO_SHA256` too.

## Validation before finishing
- Run `hugo --gc --minify --cleanDestinationDir` from the repo root after any content/layout/config change to confirm the site still builds — this matches exactly what `.github/workflows/hugo.yaml` runs in CI. The build should be warning-free; if a new `WARN deprecated:` line appears, fix it rather than ignoring it (the previous `languageCode`/`.Site.AllPages` warnings were cleaned up and the build was 100% clean as of this writing).
- `--cleanDestinationDir` matters here specifically: without it, `public/` silently accumulates stale files from old builds (this happened once already — `public/` grew to 206 MB of orphaned assets, including partial `.fdmdownload` downloads and `.eps` stock-photo sources that were never even referenced by the site, before being cleaned up).

## Repo-specific conventions
- Layout resolution: a file in the site-level [layouts/](layouts/) overrides the same path in [themes/hugo-theme-cleanwhite/layouts/](themes/hugo-theme-cleanwhite/layouts/). Since the redesign every page kind has a site-level template: `_default/baseof.html` (skeleton), `index.html` (home, text from `content/_index.md` / `_index.tr.md`: `headline`, `start_here`), `post/single.html`, `post/list.html` + `_default/post.html` (both call `partials/site/writing-list.html`; the theme's `_default/post.html` otherwise hijacks the `/post/` list because the section is named "post"), `_default/single.html`, `_default/page.html`, `_default/section.html`, `taxonomy/{category,tag,terms}.html`, `search/list.html`, `404.html`, `shortcodes/callout.html`. Shared pieces live in `layouts/partials/site/`. The old site-level `partials/nav.html`, `header.html`, `breadcrumb.html`, `sidebar.html` were removed on 2026-10-10 (unused since the redesign).
- Styling: one CSS file [assets/css/main.css](assets/css/main.css) (color tokens per `:root[data-theme]`, dark is the default) plus [assets/css/syntax.css](assets/css/syntax.css) (generated with `hugo gen chromastyles`, github-dark / github, scoped per theme; `markup.highlight.noClasses = false`). JS: `assets/js/theme-init.js` (sets the theme before paint, intentionally not deferred) and `assets/js/site.js` (theme toggle, copy buttons, TOC). All go through Hugo Pipes with minify + fingerprint + SRI. No external fonts, icon kits, CDNs or embeds; icons are inline SVG in `partials/site/icon.html`.
- Hugo here is a **snap** package: it cannot read `/tmp`. Build throwaway test copies under `~/snap/hugo/common/` instead.
- Site search is **Pagefind** (index built in CI after `hugo`, see the workflow). The UI is our own ([assets/js/search.js](assets/js/search.js), Pagefind JS API, not the bundled Default UI): the header magnifier (or `/`, Ctrl+K) turns the menu into a search box with live results, and `/search/?q=` shows the full list. Only elements with `data-pagefind-body` are indexed (post and page content); result type/date/title come from `data-pagefind-meta`, and Pagefind reads **one key per element**, so keep each meta on its own element. Locally there is no index (search shows a "live site only" note); to test, install the same version in a throwaway venv (`pip install 'pagefind[bin]==1.5.2'`) and run `python -m pagefind --site public` after `hugo`. Algolia is not used: `algolia_search = false` in [hugo.toml](hugo.toml), there is no `build_algolia_index.sh` and no `package.json`. The theme's `layouts/_default/list.algolia.json` and Algolia partials are leftovers; don't build on them.
- `static/img/` should only contain images actually referenced from content, layouts, or `hugo.toml` — it was cleaned of ~33 MB of unreferenced files once already (stray stock-photo candidates, a stray `.zip`, license `.txt` files); don't let new unused assets accumulate there, since Hugo copies everything under `static/` into the build output regardless of whether it's linked.

## Change safety rules
- Deploy is via **GitHub Actions** ([.github/workflows/hugo.yaml](.github/workflows/hugo.yaml)), triggered on push to `main` — there is no more `deploy.sh` and no more "build locally, commit `public/`, push" workflow. The workflow builds with `hugo --gc --minify --cleanDestinationDir` using a dynamic `baseURL` from `actions/configure-pages`, then deploys via `actions/upload-pages-artifact` + `actions/deploy-pages`. **One-time manual setup still required on GitHub**: repo Settings → Pages → Source must be set to "GitHub Actions" (not a branch) for this to take effect.
