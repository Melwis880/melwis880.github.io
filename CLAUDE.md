# CLAUDE.md

## Must-follow constraints
- **There is no theme** (since 2026-10-10): `hugo-theme-cleanwhite` was removed and every template lives in the site-level [layouts/](layouts/). Don't add a `theme =` line or a `themes/` folder back. With no theme there is no fallback layer: a page kind without a site-level template makes Hugo print a `WARN found no layout file` line (caught by the warning-free build rule below), not a silent fall back to old Bootstrap/jQuery templates.
- If vendored code is ever added again (a theme, a module), track it as plain files. Never commit a nested repo with its own `.git` (a **gitlink**) without `.gitmodules`: the old theme was once tracked that way, and CI silently broke because `actions/checkout` got an *empty* directory. `git clone`-ing something into the repo creates exactly that.
- `public/` is **only a build output directory** (git-ignored, regenerated by `hugo`). It is not, and never was, its own git repository — an earlier version of this doc claimed otherwise; that was wrong. Never hand-edit files under `public/`.
- The site is **bilingual (since 2026-10-09)**: English is the default language at `/`, Turkish lives under `/tr/` (`[languages]` in [hugo.toml](hugo.toml)). Every page gets both versions as translation pairs: `foo.md` + `foo.tr.md` (or `index.md` + `index.tr.md` in a bundle). Per-language tagline/SEO params and menus live under `[languages.en]` / `[languages.tr]`, UI strings in [i18n/](i18n/). The language switch in `layouts/partials/site/header.html` links to the page's translation, falling back to that language's home.
- Menu URLs are written **with the language prefix** (`/tr/projeler/`) and rendered with `relURL`, not `relLangURL`, so single-language static pages like `/kart/` don't become `/tr/kart/`. Write in-content links the same way: full path including `/tr/` for Turkish pages.
- Keep `markup.goldmark.renderHooks.link.useEmbedded = "never"`: on multilingual sites Hugo auto-enables its embedded link hook, which tried to publish `/kart/` as a resource and broke the build while `static/` was also mounted as `assets`. That mount was removed on 2026-10-10, but re-enabling the hook needs its own test; in-content links are written as full paths anyway.
- Positioning: this is an AI Automation Consultant portfolio + case studies site, not a cybersecurity blog. Only cite projects from the "Public proof" list in the owner's private profile notes (kept outside this repo; the path is in Claude's local memory); label demos as demos; never use "Engineer" as a job title before graduation. A post's type is its first category, one of `case-study`, `field-note`, `research` (labels and icons come from i18n `type-*` keys and `partials/site/icon.html`); tags are ASCII slugs (`n8n`, `python`, `ai-agents`, `automation`). Titles don't repeat the type ("Case study: ...") since the type label shows it. `ai_use` (`edit` | `draft`) adds the AI-use note under a post; only set it to what is actually true for that post.
- No em dashes in published copy.
- Personal data: the only contact email anywhere on the site (including `/kart/`) is `muharremmeric.ordu@gmail.com`. Never add a phone number, WhatsApp link, or any other personal email. Commits must use the GitHub noreply author email already set in `git config`; GitHub rejects pushes with a private address.
- The main site runs under a meta CSP (`layouts/partials/site/head.html`): `script-src 'self' 'wasm-unsafe-eval'` (WASM is for Pagefind), `style-src 'self'`, `img-src 'self' data:`. No inline `<script>`/`<style>`, no `style=`/`on*=` attributes, no external resources; put JS/CSS in `assets/` through Hugo Pipes. Don't loosen the policy to fix a violation without finding its cause first. Pagefind excerpts are rendered without `innerHTML` (only `<mark>` becomes an element); keep it that way.
- `/kart/` runs under a strict CSP: no inline `<script>`/`<style>`, no `onclick`, no external resources. JS lives in `static/kart/kart.js` (vCard), the QR code is `static/kart/qr.svg`, styles come from the precompiled `static/kart/kart.css` (Tailwind v3.4.17 standalone CLI). A new Tailwind class in `index.html` will not work until `kart.css` is rebuilt; the Tailwind input/config were not kept, so recreate them (outside `static/`, e.g. `tools/kart/`) before the first class change.
- CI pins: pagefind is pinned to 1.5.2, actions are pinned by SHA, and the Hugo `.deb` is verified with `HUGO_SHA256` in [.github/workflows/hugo.yaml](.github/workflows/hugo.yaml). Bumping the Hugo version means updating `HUGO_SHA256` too.

## Validation before finishing
- Run `hugo --gc --minify --cleanDestinationDir` from the repo root after any content/layout/config change to confirm the site still builds — this matches exactly what `.github/workflows/hugo.yaml` runs in CI. The build should be warning-free; if a new `WARN deprecated:` line appears, fix it rather than ignoring it (the previous `languageCode`/`.Site.AllPages` warnings were cleaned up and the build was 100% clean as of this writing).
- `--cleanDestinationDir` matters here specifically: without it, `public/` silently accumulates stale files from old builds (this happened once already — `public/` grew to 206 MB of orphaned assets, including partial `.fdmdownload` downloads and `.eps` stock-photo sources that were never even referenced by the site, before being cleaned up).

## Repo-specific conventions
- Layouts: every page kind has a template in [layouts/](layouts/): `_default/baseof.html` (skeleton), `index.html` (home, text from `content/_index.md` / `_index.tr.md`: `headline`, `start_here`), `post/single.html` + `notes/single.html` (both only call `partials/site/article.html`, the post page body; its header comment lists the front matter fields), `notes/list.html`, `post/list.html` (calls `partials/site/writing-list.html`; the old `_default/post.html` override was removed on 2026-10-10, output byte-identical), `home.rss.xml` (home RSS lists only posts and notes, same filter as `index.html`; About/Projects/Now stay out of the feed. `build: {list: local}` is not the fix: it also drops those pages from the sitemap), `_default/single.html`, `_default/projects.html` (`layout: projects`; boxes come from [data/projects.yaml](data/projects.yaml), one record per project with `en`/`tr` texts: adding a project is one record, never a template edit; only Public proof projects, numbers identical to the case study), `_default/about.html` (`layout: about`; `heading`, `greeting` and `stack` in front matter, sections in Markdown with the `{{< stack >}}` and `{{< contact >}}` shortcodes; contact details appear only in that section and come from `params.social`), `_default/now.html` (`layout: now`, `/now/` + `/tr/simdi/`; the date at the top is the front matter `lastmod`, update it with the text about once a month; keep the fixed `date`: without it Hugo uses `lastmod` as the publish date and a `lastmod` that is still in the future in UTC drops the page from the build), `_default/section.html`, `taxonomy/{category,tag,terms}.html`, `search/list.html`, `404.html` (GitHub Pages serves the root `/404.html` for every missing URL, `/tr/...` included, so it also carries a one-line version in the other language via the `notFoundOther*` i18n keys; `/tr/404.html` is not generated: `disableKinds = ["404"]` under `[languages.tr]`), `sitemap.xml` (copy of Hugo's embedded sitemap, output byte-identical; only change: the empty notes page is left out), `shortcodes/callout.html`. Shared pieces live in `layouts/partials/site/`; `partials/webp-image.html` returns the WebP URL of an image (used for a front matter `image:` override of og:image). The old site-level `partials/nav.html`, `header.html`, `breadcrumb.html`, `sidebar.html` were removed on 2026-10-10 (unused since the redesign).
- Writing: [WRITING.md](WRITING.md) is the content guide (types, Turkish-first workflow, structure, proof rules, pre-publish checklist). New content comes from [archetypes/](archetypes/) (`post.md`, `notes.md`; Turkish headings for `.tr.md` files): `hugo new content post/<slug>.tr.md` + `post/<slug>.md`. Archetypes start with `draft: true` and `TODO:` lines; `partials/site/article.html` prints a build `WARN` for a non-draft page that still contains `TODO:`, so the warning-free rule catches it.
- Notes (TIL) live in `content/notes/` (since 2026-10-11): a section, not a category; type `note` comes from the section (`partials/site/post-type.html`). No menu item: notes appear in the Writing list (`partials/site/writing-list.html`, same `post`+`notes` filter as home and RSS) with a "Note" filter chip that links to `/notes/` and only shows when published notes exist; on `/notes/` pages the Writing menu item is highlighted. There is deliberately no `content/notes/_index*.md` (the list title comes from i18n `type-note-plural`). With only draft notes Hugo still renders an empty `/notes/`; it then says "more soon", gets `noindex` and stays out of the sitemap.
- Share images: posts and notes get a 1200x630 JPG card drawn at build time by `partials/site/share-image.html` (type, title, name and domain on `assets/img/share/bg.png`, font `assets/fonts/DejaVuSans-Bold.ttf`, license next to it; the font is only used at build time and never published). Other pages use `params.header_image` cropped to 1200x630 JPG; front matter `image:` overrides both. `images.Text` wraps about 20 px before the right edge, so the title is drawn on a 1140 px wide crop and overlaid; Go's `upper` breaks Turkish İ, so the type label is not uppercased.
- Styling: one CSS file [assets/css/main.css](assets/css/main.css) (color tokens per `:root[data-theme]`, dark is the default) plus [assets/css/syntax.css](assets/css/syntax.css) (generated with `hugo gen chromastyles`, github-dark / github, scoped per theme; `markup.highlight.noClasses = false`). JS: `assets/js/theme-init.js` (sets the theme before paint, intentionally not deferred) and `assets/js/site.js` (theme toggle, copy buttons, TOC). All go through Hugo Pipes with minify + fingerprint + SRI. No external fonts, icon kits, CDNs or embeds; icons are inline SVG in `partials/site/icon.html`.
- Hugo here is a **snap** package: it cannot read `/tmp`. Build throwaway test copies under `~/snap/hugo/common/` instead.
- Site search is **Pagefind** (index built in CI after `hugo`, see the workflow). The UI is our own ([assets/js/search.js](assets/js/search.js), Pagefind JS API, not the bundled Default UI): the header magnifier (or `/`, Ctrl+K) turns the menu into a search box with live results, and `/search/?q=` shows the full list. Only elements with `data-pagefind-body` are indexed (post and page content); result type/date/title come from `data-pagefind-meta`, and Pagefind reads **one key per element**, so keep each meta on its own element. Locally there is no index (search shows a "live site only" note); to test, install the same version in a throwaway venv (`pip install 'pagefind[bin]==1.5.2'`) and run `python -m pagefind --site public` after `hugo`. Algolia is not used: there is no Algolia setting in [hugo.toml](hugo.toml), no `build_algolia_index.sh` and no `package.json`.
- **Images go in `assets/img/`** (a post's images in `assets/img/<post-slug>/`) and are linked from Markdown as `/img/...`, e.g. `![Flow](/img/flx-case-study/flow.png)`. The render-image hook ([layouts/_default/_markup/render-image.html](layouts/_default/_markup/render-image.html)) and `partials/webp-image.html` find them with `resources.Get` and publish only a WebP version. `static/` is no longer mounted as `assets` (since 2026-10-10), so an image put in `static/img/` is copied as-is and is **not** converted to WebP (the build doesn't fail, the original file is used). Page bundles are not supported either: the hook checks `resources.Get` only, not `.Page.Resources`. `static/img/` is only for files served unprocessed at a fixed URL (today just `favicon.ico`). Hugo copies everything under `static/` into the output whether it's linked or not, so keep it free of unused files (cleaned of ~33 MB once, and of 1.27 MB more on 2026-10-10).

## Change safety rules
- Deploy is via **GitHub Actions** ([.github/workflows/hugo.yaml](.github/workflows/hugo.yaml)), triggered on push to `main` — there is no more `deploy.sh` and no more "build locally, commit `public/`, push" workflow. The workflow builds with `hugo --gc --minify --cleanDestinationDir` using a dynamic `baseURL` from `actions/configure-pages`, then deploys via `actions/upload-pages-artifact` + `actions/deploy-pages`. **One-time manual setup still required on GitHub**: repo Settings → Pages → Source must be set to "GitHub Actions" (not a branch) for this to take effect.
